# Squeek Maze design system

## Overview

Squeek Maze is a small arcade game for desktop and touch players. Its visual character pairs a cream page and warm gold controls with a dark, softly rounded game cabinet. Squeektoshi and all gameplay art are canvas drawings, so the hamster theme remains consistent without external image services. The interface gives the maze first priority and places the short guide beside it on wide screens and below it on phones.

The canonical sources are `src/styles.css` for the interface and `src/draw.js` for game art. `index.html` defines semantic screens; `src/main.js` binds their state. The included favicon and share card are generated by `scripts/generate-art.mjs` using the same drawing functions.

Characters remain distinct by shape and behavior as well as hue.

The DOM overlay uses `#182017d9`. Measured samples under its menu heading had a minimum contrast of 10.69:1; description and metadata samples were at least 7.15:1. This measurement composes the computed overlay alpha with actual maze pixels sampled every four CSS pixels under the text boxes. It is not a claim about every pixel or all dynamic states. The automated design probe passed its solid-background text checks; coverage limits are in `artifacts/validation.md`.

## Typography

The local Latin Nunito variable font lives at `public/nunito-latin.woff2` and is declared for weights 400–800. The family stack is `Nunito, ui-rounded, "Trebuchet MS", sans-serif`. Used weights are 400 for body, 600 for navigation/secondary controls, and 800 for headings, numbers, and primary actions. `font-synthesis: none` avoids simulated faces. The font license is kept beside the asset.

| Size token | At default root | Use |
| --- | ---: | --- |
| `--text-caption` | 14px | Captions, status, metadata |
| `--text-body` | 16px | Body, inputs, button text |
| `--text-heading` | 20px | Small headings, mobile statistics |
| `--text-stat` | 24px | Statistics, compact panel titles |
| `--text-title` | 32px | Desktop panel headings, phone product title |
| `--text-display` | 56px | Desktop product title and countdown numeral |

Headings use weight 800, balanced wrapping, and 1.15 line-height, with the product title at 1.05. Body copy uses 1.5; explanatory guide/dialog content uses 1.6. Display title tracking is −0.045em on desktop and −0.035em on phones. Other text uses natural tracking. Statistics, progress counts, final scores, and leaderboard values use tabular numerals. Input text stays at 16px. Names wrap within the leaderboard instead of being truncated.

## Layout

The `.site-shell` is at most 1120px wide, including 32px side padding. The shared spacing tokens are 4, 8, 12, 16, 24, 32, and 48px (`--space-1` through `--space-7`). Use the smaller steps within controls and the larger steps between sections. Header, page heading, and navigation can wrap when text grows.

The wide `.play-layout` has a first column up to 688px, a sidebar of at least 240px, and a 40px gap. Cabinet statistics share a four-column grid. The 840×840 backing canvas always draws a 21×21 square maze and scales to its CSS width. On wide, short viewports, `.board-wrap` width is capped by `max(360px, 100svh - 220px)`. Starting a run scrolls the cabinet into view if its bottom is below the viewport.

Maze and overlay share one grid area. The overlay participates in sizing, so larger text can increase the cabinet height instead of being clipped. Its contents are at most 380px wide. Game geometry remains square even when a larger overlay makes the surrounding cabinet taller.

| Breakpoint | Adaptation |
| --- | --- |
| At most 62rem | 24px shell padding, 250px sidebar, 28px column gap, compact menu mascot and statistics |
| At most 48rem | One-column cabinet followed by guide; shell at most 640px with 20px padding; title 32px; full-width live status with two text lines; visible direction buttons; secondary guide sections share two columns |
| At most 24rem | 12px page margins, mascot-only header brand, 16px statistics, smaller decorative mascot, tighter overlay gaps |

Tested rendered widths: 320, 390, 850, and 1440px. The first 390px screen includes the product title and Play action. A separate 200% root-text enlargement check reflows content without horizontal overflow; native browser zoom was not tested. An RTL overflow smoke check ran, but the delivered copy and layout are English and not a translated RTL product.

## Elevation & depth

The cabinet has a single `0 12px 30px #493c2818` shadow and no border. Page groups use spacing and restrained structural separators. Live status, guide art, and the wheel note use flat tonal surfaces. The native instructions dialog has a `#1e211b99` backdrop with 3px blur. The maze overlay darkens the live canvas without replacing it with an image.

The background is a fixed canvas below the document content. Its wheel outlines use very low opacity and turn slowly. It never accepts pointer events. This is decoration, not state communication.

## Shapes

- `--radius-panel`: 24px for large desktop panels; the mobile cabinet uses 20px.
- `--radius-control`: 12px for primary controls; board corners also use 12px.
- Neutral icon controls and input fields use 10px radii; mate art uses 14px; status and notes use 12–16px depending on width.
- Hearts, hamster ears, peanuts, snakes, and wheel geometry are canvas paths; reuse `src/draw.js` rather than introducing a separate icon or image family.

## Components

| Component/pattern | Source | Behavior and states |
| --- | --- | --- |
| `.button` / `.button-primary` | `src/styles.css`, `index.html` | One gold primary action per screen; 48px default minimum height, 44px on phones; hover fill and 0.96 press scale when motion is allowed |
| `.icon-button` | Same | Named sound/pause controls, native disabled state, 40–44px targets; canvas icon carries no duplicate accessible text |
| `.live-status` | `src/main.js` `applyStatus`, `src/status.js` | Checking, RUNNING, SLEEPING, unavailable; state appears in text, not only a colored dot; no unverified boost |
| `.scoreboard` / `progress` | `index.html`, `src/main.js` `updateHud` | Level, score, saved best, three lives, and peanut progress; lives have a named image role |
| `.overlay-screen` | `index.html`, `src/main.js` `updateOverlay` | Menu, countdown, pause, hit recovery, level clear, game over, and congratulations; only the current screen remains exposed |
| Score form | `#score-form`, `src/storage.js` | Real visible label, 18-character name, native submission, whitespace validation, safe text rendering, save-once success, persistent storage error with retry |
| Leaderboard | `#leaderboard-view`, `renderLeaderboard` | Dedicated hash screen; native table, top ten sorted scores, real empty state with Play action; names inserted with `textContent` |
| Instructions | `#help-dialog` | Native modal, background inertness, Escape close, focus restoration; pauses and resumes an active run |
| Touch pad | `.touch-controls`, `src/main.js` pointer handlers | Four labeled direction buttons plus swipes on the maze; only the gesture surface suppresses selection and native touch scrolling |

Keyboard focus uses a 3px outline with a 4px offset. Inside the dark overlay it becomes `#ffd08b`; the maze uses an inset `#f7d59c` outline. Forced-colors mode retains the system Highlight indicator. Pausing focuses Resume; results focus the name field; leaderboard navigation focuses its heading. Status announcements avoid announcing each peanut.

Color and transform transitions are 130ms, with `ease-out` for fill and `cubic-bezier(.2, 0, 0, 1)` for press scale. There are no entrance animations. Motion preferences initialize decorative animation off, and the footer provides an explicit toggle. The game uses `requestAnimationFrame`; essential movement is retained under reduced motion, while background rotation, mascot bobbing, bean pulse, and invincibility blinking stop.

## Do’s and don’ts

- Start an additional screen inside the existing shell, keep one visible main landmark, and reuse the six-size scale.
- Use the gold fill for the next primary action. Keep secondary navigation and utilities neutral.
- Reuse semantic color/spacing tokens for interface elements and the existing canvas functions for characters and icons.
- Keep directions beside the controls. Keep status failures playable, score errors recoverable, and local-storage scope explicit.
- Keep overlay content in the grid sizing flow. Do not restore a fixed-height, clipped text layer over the canvas.
- Do not introduce external runtime fonts, character image downloads, wallet flows, or a new icon family into this static game.

Rendered evidence, the six-domain review, corrected findings, and unperformed checks are documented separately in `artifacts/validation.md`.
